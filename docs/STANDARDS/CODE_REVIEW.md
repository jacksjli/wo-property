# Code Review 规范

> **版本**：v1.0
> **最后更新**：2026-05-05

---

## 1. 概述

Code Review 是保证代码质量的重要环节，通过团队协作审查代码，发现问题、分享知识、统一风格。

---

## 2. Review 原则

### 2.1 Reviewer 原则

```
✓ 应该：
  - 理解代码的意图
  - 关注代码质量、安全性、性能
  - 提供建设性的反馈
  - 认可好的代码实践

✗ 不应该：
  - 过于挑剔无关紧要的格式问题
  - 用个人偏好替代团队规范
  - 让 ego 影响反馈质量
  - 拖延 review（尽快响应）
```

### 2.2 Author 原则

```
✓ 应该：
  - 保持 PR 小而专注
  - 编写清晰的 PR 描述
  - 准备好测试用例
  - 认真对待反馈

✗ 不应该：
  - 在 PR 中混入无关变更
  - 忽略 Reviewer 的问题
  - 过度防御或争论
```

## 3. Review 检查清单

### 3.1 代码质量

| 检查项 | 说明 |
|--------|------|
| 命名规范 | 变量、方法、类名是否清晰易懂 |
| 代码重复 | 是否有重复代码可以抽取 |
| 复杂性 | 逻辑是否过于复杂，需要拆分 |
| 注释 | 复杂逻辑是否有必要注释 |

### 3.2 功能正确性

| 检查项 | 说明 |
|--------|------|
| 功能完整 | 是否实现了需求的功能 |
| 边界条件 | 是否处理了空值、边界值 |
| 错误处理 | 异常情况是否正确处理 |
| 并发安全 | 多线程环境是否安全 |

### 3.3 安全性

| 检查项 | 说明 |
|--------|------|
| SQL 注入 | 是否使用参数化查询 |
| XSS | 输出是否做转义处理 |
| 认证授权 | 敏感操作是否验证权限 |
| 敏感数据 | 密码等是否正确加密存储 |

### 3.4 性能

| 检查项 | 说明 |
|--------|------|
| 数据库 | 是否正确使用索引 |
| N+1 查询 | 是否有循环查询问题 |
| 缓存 | 是否合理使用缓存 |
| 异步 | 是否正确使用异步 |

### 3.5 测试

| 检查项 | 说明 |
|--------|------|
| 单元测试 | 核心逻辑是否有测试 |
| 边界测试 | 边界条件是否有测试 |
| 错误测试 | 异常情况是否有测试 |

## 4. 反馈等级

### 4.1 必须修复 (Must Fix)

```
标签：must-fix
颜色：红色

含义：代码存在严重问题，必须修复后才能合并

示例：
- 安全漏洞
- 明显 bug
- 破坏现有功能
- 违反团队核心规范
```

### 4.2 建议修改 (Should Fix)

```
标签：should-fix
颜色：橙色

含义：代码有改进空间，建议修改

示例：
- 性能问题
- 代码可读性差
- 可以抽取的重复代码
- 缺少必要的错误处理
```

### 4.3 值得考虑 (Consider)

```
标签：consider
颜色：蓝色

含义：这是一个好建议，但不一定必须

示例：
- 更好的命名
- 更优雅的实现方式
- 改进代码结构
```

### 4.4 问题或讨论 (Nit/Question)

```
标签：nit / question
颜色：灰色

含义：这是一个小问题或疑问

示例：
- 拼写错误
- 格式不一致
- 理解不清的地方需要确认
```

### 4.5 认可 (Praise)

```
标签：praise
颜色：绿色

含义：这段代码写得很好，值得学习

示例：
- 优雅的实现
- 精彩的解决方案
- 清晰的注释
```

## 5. 响应时间

| PR 优先级 | 响应时间 | 合并时间 |
|-----------|----------|----------|
| 紧急修复 | 1 小时内 | 尽快 |
| 普通 PR | 24 小时内 | Review 通过后 |
| 大型 PR | 48 小时内 | Review 通过后 |

## 6. 工具支持

### 6.1 GitHub PR 模板

```markdown
## 概述
[简要描述本次变更]

## 变更类型
- [ ] 新功能
- [ ] Bug 修复
- [ ] 重构
- [ ] 文档更新

## 变更内容
- [变更点1]
- [变更点2]

## 测试情况
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试通过

## 关联 Issue
Closes #123
```

### 6.2 自动化检查

```
PR 自动化检查项：
□ 代码格式检查 (Prettier/ESLint)
□ 单元测试
□ 集成测试
□ 安全扫描
□ 依赖检查
```
